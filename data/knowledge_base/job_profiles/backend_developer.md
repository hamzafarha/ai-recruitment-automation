# Job Profile — Backend Developer

## Mission

Design and build the server-side services, APIs and data storage that products rely on. The Backend Developer is
responsible for correctness, performance, security and maintainability of these services.

## Responsibilities

- Design and implement REST (or GraphQL) APIs.
- Model data and write efficient queries for relational and NoSQL databases.
- Write automated tests and take part in code reviews.
- Integrate services through messaging and asynchronous processing.
- Diagnose and fix production issues together with the operations team.

## Must-have requirements

- **M1** At least one backend language in production: Python, Java, Go, C# or Node.js.
- **M2** A web framework for that language: FastAPI, Django or Flask; Spring Boot; .NET; Express.
- **M3** Relational databases and SQL: schema design, indexes, transactions.
- **M4** REST API design: resources, status codes, versioning, authentication.
- **M5** Automated testing (unit and integration) and version control with Git.

## Nice-to-have requirements

- **N1** Docker and CI/CD pipelines.
- **N2** NoSQL or caching: MongoDB, Redis, Elasticsearch.
- **N3** Messaging: Kafka, RabbitMQ.
- **N4** Cloud services: AWS, Azure or GCP.
- **N5** Microservices architecture and observability (logs, metrics, traces).

## Equivalent and transferable skills

- Backend languages are transferable: a strong Java developer applying for a Python role meets M1 partially
  (grade 2 is typical) if they show at least one Python project.
- PostgreSQL, MySQL, SQL Server and Oracle are equivalent for M3.
- Full-stack developers usually meet M1–M4; check the depth of backend work, not only frontend.
- QA or support engineers who wrote automation code meet M5 but rarely M2–M4.

## Experience by level

- **Junior**: one language and framework, academic or personal API projects, an internship.
- **Mid-level**: 2–5 years building and maintaining production services.
- **Senior**: 5+ years, designed service architecture, owned performance or reliability improvements.

## Red flags

- Many languages listed, none with a described project.
- Only maintenance of legacy code with no design responsibility, for a senior position.

## Role-specific interview questions

- "Design an API to manage job applications: resources, endpoints, status codes."
- "A query became 10 times slower after a release. How do you find the cause?"
- "How do you make an API endpoint safe to retry?"
